        What counts as a duplicate? Same Full Question ID as a row already in the database → skipped and listed above.
        Rejected? Rows missing required metadata (Question ID, Question, positive Marks, Board, Class, Subject, Chapter, Topic, valid Difficulty, Question Type, Answer, or Source Paper) are not added to the question bank. Clear encoding corruption and malformed multipart data are rejected with a reason; fix them and re-upload.
        Truncation policy: rows matching any truncation check (ending ellipsis, unmatched brackets/quotes, dangling ending, or Excel's 32,767-character cell limit) are flagged and rejected, never inserted. Rejected IDs, row numbers, excerpts, and signals appear below and are recorded in rejected_questions. Legitimate symbols (→, ≤, Greek letters, and scientific notation) are preserved.
        Structured questions: content_features values such as DIAGRAM;GRAPH are stored as a PostgreSQL array, and structure_data must be valid JSON. Multipart labels/marks are checked; invalid structure is rejected. Accepted rows get a validation status, and review flags are stored in the database.
        Excel tip: only the first sheet is read for the question-bank path. Column names are flexible (QID, Question Text, Type… all work).

        Blueprint path: The original JSON, CSV, or XLSX file is sent as multipart binary to the shared webhook and parsed in n8n; the browser does not convert it into a Blueprint JSON model. All XLSX worksheets and source columns are inspected; unknown fields and unsupported worksheets are preserved and reported. A complete master sheet with Chapter_No, Chapter_Name, and Unit_Domain produces a separate distinct chapter pool while every subtopic row remains a slot; a dedicated Chapter_Pool sheet takes precedence. No chapter-level target weights are inferred from row marks. CSV supports nested choices, subparts, rules, section definitions, and a chapter pool only when represented as JSON cells. The 38-slot/80-mark check applies only to the reserved `CBSE-C12-MAT-041-MASTER-v1` complete-paper identity when `rules.complete_paper=true`; production matrices must use a distinct identity. Missing section definitions are clearly marked as derived from slots. Missing subject references remain null; the uploader never creates reference rows.
        Version safety: the Blueprint file is validated and conflict-checked on the server in the same direct upload request before any write. No published blueprint is overwritten. A new published version may retire an existing published sibling only after explicit confirmation for the exact ID returned by the server; both records remain available for traceability. The same webhook handles both modes; its upload-type IF routes this request to the Blueprint branch.
